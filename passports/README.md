# Паспорта датасетов и правила объединения

Сгенерировано `make_passports.py`. Исходные файлы не изменяются.

## Сводка

| Датасет | Строк | Колонок | Гранулярность | Ключ | Период |
|---|---:|---:|---|---|---|
| `Seasons_Stats.xls` | 24,691 | 53 | игрок × сезон × команда (+`TOT`) | `(Player, Year)` не уникален, ID нет | 1950–2017 |
| `players.csv` | 4,685 | 25 | 1 игрок | `_id` (B-Ref ID) | карьера |
| `salaries_1985to2018.csv` | 14,163 | 8 | игрок × сезон × команда | `(player_id, season)` не уникален | 1985–2018 |

## Как связаны

- `players._id` = `salaries.player_id` — точное совпадение: **2,408/2,408** ID из зарплат
  (100.0%); у **51.4%** игроков из players есть зарплата.
- `Seasons_Stats` не содержит ID. Связь только через имя → `players._id`:
  - точное совпадение имён: **3,755/3,921** (95.8%);
  - после нормализации (регистр, пунктуация, `*`): **3,881/3,919** (99.0%);
  - неоднозначных нормализованных имён (разные игроки с одинаковым именем): **43** — join по имени для них запрещён;
  - примеры ненайденных имён: billyray, butchvan, derrickjones, dickvan, didierilungambenga, eddielee, georgebon, horaciollamas.

## Правила объединения

1. **Канонический ключ игрока** — `players._id` (= `salaries.player_id`). Для stats сначала строить
   `Player → _id` по нормализованному имени, неоднозначные имена разбирать вручную (позиция/возраст/команда/год).
2. **Ключ сезона** — `Seasons_Stats.Year == salaries.season_end` (`season_start = Year - 1`).
   Проверено на Alaa Abdelnaby: stats 1991 ↔ salary 1990-91.
3. **Stats:** удалить 67 пустых строк; для итогов игрока за сезон брать `Tm == "TOT"`
   (совпадает с суммой строк команд по G/PTS в 99.8%/99.8% пар), иначе — сумма по командам.
4. **Salaries:** для полной зарплаты за сезон суммировать `salary` по `(player_id, season_end)`
   (трейды разбивают выплаты на несколько строк).
5. **Покрытие join stats ↔ salaries** на пересечении 1985–2017:
   - строк stats: **17,100**;
   - сопоставлено по `(pid, season_end)`: **14,755** (86.3%);
   - нет `pid` (не найдено или неоднозначное имя): **490**, из них неоднозначных **326**;
   - `pid` есть, зарплатной строки нет: **1,855**.
6. Неполные сезоны зарплат: **1987 (40 строк), 1990 (64 строк)** —
   не трактовать отсутствие зарплаты как «не играл».
7. `players.career_*` — карьерные итоги, не сезонные: для мержа на уровне сезона не использовать,
   кроме справочных атрибутов (`position`, `height`, `weight`, `birthDate`, `college`, `draft_*`).

## Риски

- **Join по имени — главный риск**: 1.0% имён не сопоставлены;
  неоднозначных нормализованных имён: **43** (326 строк stats в 1985–2017 затронуто).
  Точный мерж без внешнего ID-маппинга невозможен.
- `Year == season_end` — соглашение подтверждено выборкой, но проверять на новых данных.
- Неполные сезоны зарплат: 1987, 1990; 2018 есть только в зарплатах.
- Аномалии источников: 67 пустых строк stats, 4 строки зарплат без команды, `"-"` в `players.career_*`.
- Денежные суммы не приведены к инфляции; межгодовые сравнения некорректны без дефлятора.
